MT5 EA Not Trading? 10 Checks Before Changing Your Bot

Use this checklist to identify whether your Expert Advisor is waiting for a signal, blocked by a setting or rejected by the broker. Capture the cause before changing the strategy.

NextGen Tech Solutions · Published 1 October 2026

Start with the evidence: an EA can be running while no valid entry exists. First find out whether it is waiting for a setup, refusing a setup, or sending an order that the broker rejects.

10 checks when an MT5 Expert Advisor is not opening trades

  1. Confirm the EA is attached and initialized. Check the intended chart and the Experts log after attaching the EA. An initialization failure, missing indicator or invalid input needs fixing before you investigate entry rules. An MT4 EX4 file is not an MT5 EX5 build.
  2. Check the platform Algo Trading control. MT5 has a terminal-level automated-trading permission. Seeing prices update or indicator objects appear does not prove the EA can submit orders.
  3. Check this EA's own permission. Open its properties and check the automated-trading setting. Terminal permission and program permission are separate checks; one enabled switch does not establish both.
  4. Check the account and connection. Confirm the correct broker server and an active connection. A login with the investor password is read-only. Account-level or broker-side restrictions can also prohibit automated orders.
  5. Use the broker's exact symbol. EURUSD, EURUSD.a and EURUSDm are different names. Verify that the symbol selected by the EA exists, has prices and matches the configured instrument. Multi-symbol EAs need data for every instrument they inspect.
  6. Confirm a valid setup actually occurred. Compare the candle, timeframe and input settings with the written entry rule. A strategy that waits for a candle close may deliberately ignore an intrabar signal. Ask for a log showing which entry condition passed or failed.
  7. Inspect the filters. Session hours, server-time conversion, spread limits, a daily trade cap, existing-position checks and an equity guard can block an otherwise valid entry. Identify the active blocker before changing a limit.
  8. Validate volume and stops. Requested lots must match the broker's volume constraints. Stops must be on the correct side and meet the symbol's distance and price rules. A position-size estimate is not automatically a valid broker order.
  9. Separate tester results from live integrations. For an EA that uses MQL5 WebRequest, the server URL must be allowed in terminal options. WebRequest is unavailable inside the Strategy Tester; test the network path separately or replay recorded inputs through a test adapter.
  10. Capture the order result. If the EA reached order submission, record the trade result's retcode, comment, requested volume, symbol and prices. Reattaching the EA repeatedly will not explain a broker rejection. Reproduce the issue on a demo account with one controlled change at a time.

Common MT5 trade return codes and what to check

These are broker trade-server return codes in MqlTradeResult.retcode. They are a different diagnostic channel from the terminal's GetLastError() value. Always keep the code's name and the broker comment together.

CodeMeaningNext check
10014Invalid volumeCompare requested lots with the symbol's minimum, maximum and volume step.
10016Invalid stopsCheck stop direction, price precision and the broker's required stop distance.
10018Market closedConfirm this symbol's trading session and broker server time.
10019Insufficient moneyInspect free margin and the margin required for the requested order.
10027Client terminal disables automated tradingRecheck terminal Algo Trading permission and the EA's own setting.
10030Invalid filling typeUse a filling policy supported by the symbol and the intended order type.

A useful fix changes the cause and then demonstrates a valid order result. Adding unlimited retries to the same rejected request can obscure the cause and introduce duplicate-order risk.

What to send your MT5 developer

Provide a small reproducible report: the EA version, terminal build, broker server, exact symbol, timeframe, input settings and the server-time timestamp of the expected trade. Add the nearby Experts and Journal lines, the trade retcode and an explanation of the entry condition you expected to pass.

Describe whether the issue also happens in the Strategy Tester or on a demo account. For symbol or sizing errors, include the relevant symbol specification. Hide account passwords, API tokens and unrelated personal details; a diagnostic report does not need those secrets.

Common questions

Why does my EA draw objects but never open a trade?

Chart drawing and order submission are separate operations. The EA may have trading disabled, lack an entry condition, hit a filter or receive a broker rejection. Log those stages separately.

Why does an EA trade in the tester but not on my account?

Compare symbol settings, inputs, account permissions and the actual market conditions. External network access is another difference: a WebRequest-based integration cannot run unchanged in the Strategy Tester.

Can you repair an existing EA?

We can scope MQL4/MQL5 debugging when the source code or a clearly reproducible problem is available. Send the diagnostic details above so the repair can have a defined acceptance test.
