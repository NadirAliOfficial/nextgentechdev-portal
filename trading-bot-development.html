What a custom MT5 EA project should define before coding

A reliable Expert Advisor starts with explicit rules. The specification should state the exact entry condition, invalidation condition, stop-loss and take-profit logic, position-sizing method, session filters, maximum simultaneous trades and what happens when data or execution is unavailable. Terms such as “strong trend” or “good momentum” need measurable definitions so the same market state produces the same decision in testing and production.

Typical deliverables

  • MQL5 or MQL4 source code and compiled build where applicable.
  • Configurable inputs for strategy and risk parameters.
  • Broker-safe lot normalization and symbol-property handling.
  • Execution, error and trade-management logs.
  • Backtest/validation setup instructions and handover notes.

Backtesting and forward validation

Strategy Tester results are useful only when the assumptions resemble the intended broker and market. Tests should include realistic spread and execution costs, then be checked on data that was not used to tune the rules. For parameterized systems, walk-forward or out-of-sample testing can reveal whether performance depends on one narrow historical period.

Win rate alone is not enough. A validation report should also inspect maximum drawdown, profit factor, expectancy, average win/loss, exposure, trade count and sensitivity to spread or slippage. Development can implement and test a strategy, but future returns cannot be guaranteed.

When a bridge or API is needed

Not every system should live entirely inside MT5. TradingView signals, Telegram messages, external machine-learning services or portfolio logic can require an API bridge. In those cases, the design should include authentication, durable event IDs, deduplication, retry behavior and reconciliation with the actual broker state.
